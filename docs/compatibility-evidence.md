# Проверка данных между версиями

Переход с образов `deploy-2026.10.28` на `deploy-2026.10.28-2` проверен в
[изолированном CI](https://github.com/prince174/uter_deploy/actions/runs/40645102075)
для Compose и Kubernetes. В тесте используется временная Qwen через Ollama.
До обновления создаются тестовые записи Redis: строка, хеш, список, множество,
сортированное множество и ключ с TTL. После обновления проверяются их значения и TTL,
а также HMAC-цепочка аудита. Экспортированный снимок Redis также запускается в
отдельном временном Redis, где проверяются эти типы данных и срок действия ключа.

Эта проверка подтверждает только перечисленные синтетические данные и выбранные
образы. Она не доказывает совместимость всех пользовательских данных, сессий,
согласований, внешних хранилищ и моделей. Для каждой новой пары выпускаемых версий
нужно отдельно проверить применимые сценарии и подтвердить значения `data_epoch` и
`upgrade_from`. Значения, используемые CI для тестовых подписанных комплектов, не
являются декларацией совместимости настоящего релиза.

В [отдельном прогоне](https://github.com/prince174/uter_deploy/actions/runs/40648769218)
Uter восстановлен из копии в новые Compose-проект и Kubernetes-namespace и проверен
с реальной LLM. Исходные установки и их тома не перезаписывались. Переключение трафика,
внешние системы и сохранение записей после момента копирования этим не проверялись.
