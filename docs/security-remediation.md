# Исправление зависимостей готовых образов

Изменения выполняются в `uter_deploy`. Скомпилированные модули продукта берутся из
закреплённых образов; исходный checkout и работающие окружения не используются.

## Процесс проверки

1. `packaging/security-baseline.json` закрепляет исходные digest, версию установочного
   комплекта и SHA256 его архива. Конфигурация извлекается только после проверки SHA256.
2. Workflow `remediate-images.yml` сканирует исходные образы актуальной базой Trivy.
3. Guardrail и Agent собираются в минимальный runtime: Python, зависимости, библиотеки
   ОС, CA bundle, модель и скомпилированные модули. Shell и пакетный менеджер отсутствуют.
   Для оставленных библиотек сохраняются владельцы пакетов, версии, лицензии и SHA256;
   `/var/lib/dpkg/status` позволяет Trivy учитывать уязвимости оставшихся OS-пакетов.
4. Обновляются PyJWT/CA-зависимости, а в Agent — официальные FastEmbed 0.9.1 и Pillow
   13.0.0. Выполняется `pip check`; метаданные сторонних пакетов не переписываются.
   Redis обновляется в пределах ветки 7.4 с закреплённым upstream digest.
5. Проверяются импорт скомпилированных модулей и offline toxicity inference.
   Для Agent проверяются PNG/JPEG/WebP и реальный FastEmbed inference: сначала модель
   загружается во временный cache CI, затем inference повторяется без сети.
6. Итоговые образы проходят полный vulnerability/secret scan, формируется CycloneDX
   SBOM. Gate требует ноль Critical, High и secret findings, а также распознанную ОС.
   Исключений CVE и `ignore-unfixed` нет. Medium/Low остаются в отчётах.
7. Каждый слой экспортированного образа проверяется на собственные исходники.
   Только успешный run допускается в `publish-images.yml`. Публикация сохраняет
   проверенные image ID и дополнительно проверяет запрет анонимного скачивания.
8. После публикации выполняются реальные установки Compose и Kubernetes в отдельных
   GitHub runners, API-проверки и повторная проверка после перезапуска всех сервисов.
   Релиз закрепляется только после успешного завершения обеих установок.

## Артефакты

В `protected-<service>/evidence/` сохраняются `before-findings.json`, `findings.json`,
`security-summary.json`, `sbom.cdx.json`, source scan, image ID и SHA256 архива.
У Python-сервисов дополнительно сохраняются runtime inventory и результаты импорта;
у Agent — результаты проверки codecs и embeddings с сетью и без сети.

`security-summary.json` — сводка конкретного сканирования конкретного образа, а не
обещание отсутствия неизвестных уязвимостей. При обновлении базы результат может
измениться. Полные отчёты позволяют отличить исправление версии от удаления
неиспользуемого компонента и проверить, что оставшиеся библиотеки учтены.

## Повторный запуск

В Actions запустить **Remediate and gate published runtime images**. После успешного
завершения передать его run ID в **Publish private images and verify installation**.
Не использовать run с ошибкой или архивы от другой сборки. Проверки выполняются
в GitHub-hosted CI; локальный Docker daemon для них не нужен.

Установка в kind не подтверждает TLS, HA, действие NetworkPolicy, реальный внешний
LLM или миграцию данных между версиями. Удаление shell также означает, что для
диагностики внутри контейнера следует использовать Python, а не `docker exec … sh`.
