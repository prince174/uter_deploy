# Реальная LLM и управляемое обновление в изолированном CI

28.10.2026 [run 40636094811](https://github.com/prince174/uter_deploy/actions/runs/40636094811)
завершился успешно для Compose и Kubernetes. Job получает только доступ на чтение
этого репозитория и GHCR; исходники Uter и локальный стенд не используются.

Для каждого backend создаётся отдельный GitHub-hosted runner. Он скачивает установочные
архивы `deploy-2026.10.28` и `deploy-2026.10.28-2`, проверяет SHA256, поднимает Ollama
с моделью `qwen2.5:0.5b-instruct` на CPU и проверяет digest модели. Модель и runner
временные; платный API и внешние учётные данные не используются. Для теста предел
ответа установлен в 64 токена. Прокси пересылает
запросы к Ollama и считает непустые ответы и выходные токены, не записывая их тексты.

CI генерирует тестовые секреты и два подписанных временным Ed25519-ключом комплекта
для `uterctl` с образами двух указанных релизов. Затем он:

1. Создаёт управляемую установку на образах первого релиза и проверяет вход, состояние
   модели toxicity, доступность Agent и настоящий запрос к Qwen через Uter.
2. Записывает тестовое значение в Redis и проверяет HMAC-цепочку аудита.
3. Убеждается, что обновление без `backup-receipt` отклоняется.
4. Выполняет обновление на образы второго релиза с тестовым receipt.
5. Повторяет запрос к модели и проверяет состояние контроллера, образы запущенных
   контейнеров/Pod, тестовую запись Redis и неизменность первой записи аудита вместе
   с ростом цепочки.

В обоих backend счётчик успешных ответов модели вырос с 2 до 4, записи аудита — с 5 до
10; проверка Redis и цепочки прошла. Тексты запросов, ответов и секреты в отчёт не
публикуются. Прогон создаёт и удаляет только собственные временные контейнеры,
кластеры и volumes.

## Границы

- Комплекты и подписывающий ключ созданы только для теста и не являются выпущенным
  подписанным релизом. Значения версий `0.0.1`/`0.0.2` и `data_epoch=1` — тестовые;
  они не объявляют совместимость пользовательских данных при реальном обновлении.
- Receipt синтетический: создание резервной копии, её восстановление и миграция
  данных не проверялись. Контроллер не создаёт резервные копии автоматически.
- Проверена **новая установка под управлением uterctl**, затем её обновление. Переход
  уже созданной через `install.py` установки под управление uterctl не реализован и
  не проверялся. Откат реального окружения этим прогоном не проверялся.
- Модель небольшая и работает на CPU. Другие модели, провайдеры, TLS, RAG, HA,
  нагрузка и пользовательские политики требуют отдельных проверок. В kind сетевое
  действие NetworkPolicy не подтверждается.

## Повторить

В Actions вручную запустите `Test real LLM and managed upgrade in isolated CI`.
CI скачает образ Ollama, модель (~400 МБ), образы Uter и зависимости. Результаты
находятся в `real-llm-upgrade-compose-evidence` и
`real-llm-upgrade-kubernetes-evidence`. Скрипт отказывается работать вне Linux
GitHub Actions и проверяет соответствующую переменную окружения; сама эта переменная
не гарантирует изоляцию. Используйте только GitHub-hosted runner, не существующий стенд.
