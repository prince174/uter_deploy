# Подготовка подписанного комплекта

Эта инструкция предназначена для сопровождающего выпуска. Она описывает подготовку,
а не подтверждает совместимость данных или готовность автоматического восстановления.
Пока эти проверки не завершены, не объявляйте комплект готовым к обновлению данных.

## Ключ издателя

На доверенной Linux-машине создайте новый каталог вне репозитория с правами 0700:

```bash
umask 077
mkdir -p "$HOME/.local/share"
mkdir "$HOME/.local/share/uter-publisher"
python3 scripts/publisher_key.py \
  --private "$HOME/.local/share/uter-publisher/publisher-private.pem" \
  --public "$HOME/.local/share/uter-publisher/publisher-public.pem"
```

Команда не перезаписывает существующий ключ и печатает SHA256 публичного PEM-файла.
Закрытый ключ храните вне репозитория и CI, ограничьте доступ и создайте его
защищённую резервную копию. Потеря ключа потребует отдельной процедуры смены доверия;
не генерируйте незаметно новый ключ вместо старого. Доставьте пользователю публичный
ключ и его отпечаток независимыми доверенными каналами. Копия ключа рядом с комплектом
сама по себе не подтверждает, что этот комплект выпущен доверенным издателем.

## Манифест и подпись

Получите и проверьте установочный архив и его происхождение; checksum рядом с архивом
сам по себе не является независимой подписью. Убедитесь, что образы прошли проверку,
их digest соответствуют артефактам сборки, и подтвердите совместимость данных на реальных
переходах. `data_epoch` и `upgrade_from` — решения выпускающего, а не значения,
которые можно вывести из имени версии. Для первого комплекта список переходов может
быть пустым; это не объявляет его совместимым с существующими установками.

```bash
python3 scripts/release_manifest.py --inputs ./incoming --version 1.0.0 \
  --data-epoch 1 --output ./manifest.json
# Для каждого подтверждённого перехода добавьте --upgrade-from VERSION.
python3 scripts/bundle.py --manifest ./manifest.json --output ./signed-bundle \
  --key "$HOME/.local/share/uter-publisher/publisher-private.pem"
python3 uterctl.py verify --bundle ./signed-bundle \
  --key "$HOME/.local/share/uter-publisher/publisher-public.pem"
```

Приведённые номера — синтаксический пример, не заявление о выпущенной версии или
совместимости данных. Перед публикацией отдельно проверьте состав комплекта,
подпись, путь обновления, копирование и полное восстановление для Compose и Kubernetes.
Закрытый ключ, runtime-конфигурация, пользовательские секреты и данные в комплект
не включаются. Манифест `tooling_schema: 1` включает в подписанный inventory также
контроллер, необходимые скрипты, зависимости и шаблон Redis; проверка подписи
отклоняет отсутствие или изменение этих файлов. Восстановление создаёт отдельную
новую установку; подпись сама по себе не подтверждает совместимость пользовательских
данных и не переключает трафик.
