## Уязвимости (исходный отчёт 22.10)

Источник: [Trivy audit 39742961298](https://github.com/prince174/uter_deploy/actions/runs/39742961298),
образы из [сборки 39742696325](https://github.com/prince174/uter_deploy/actions/runs/39742696325).
Отчёты относятся к image ID в artifacts, не к произвольному последующему тегу.

| Образ | Critical | High | Secrets findings |
|---|---:|---:|---:|
| Guardrail | 0 | 44 | 0 |
| Agent | 3 | 60 | 0 |

Это число находок package/CVE; одна CVE может присутствовать в нескольких пакетах.
Уязвимая версия обнаружена, но достижимость эксплуатации через интерфейс Uter
отдельно не подтверждена. Нулевой результат поиска секретов не доказывает их отсутствие.

У Agent три Critical в Pillow 12.3.0: CVE-2026-112393, CVE-2026-112403,
CVE-2026-112900. В отчёте FixedVersion=13.0.0. Проверка метаданных PyPI 22.10.2026
показала: актуальный fastembed 0.9.0, как и установленный 0.8.0, требует pillow<13
на Python 3.12. Обновление только Pillow уже отклонено pip check. Не применять
--no-deps, не скрывать findings и не считать конфликт совместимости исправлением.
Следующее решение требует совместимого upstream/backport либо отдельной проверки
состава embeddings-зависимостей; удаление Pillow без проверки потребителей недопустимо.

Остальные High в отчёте Guardrail относятся к Debian-пакетам (в том числе util-linux,
acl, ncurses, systemd, perl); FixedVersion для них отсутствует. Agent дополнительно
содержит находки Pillow. Это отсутствие исправления в используемом feed для данных
пакетов, а не утверждение, что решения нигде не существует. Non-root/read-only/cap_drop
уменьшают поверхность атаки, но не отменяют CVE и не заменяют разбор достижимости.

Обновления ОС и PyJWT уже находятся в packaging/Dockerfile.security. Это отдельный
этап: protected-images сам по себе не применяет security overlay. Проверять и выпускать
нужно конкретный итоговый image ID после overlay, а не первоначальную сборку.
Аудит использует exit-code=0 для получения отчёта; зелёный workflow не блокирует
выпуск автоматически и не является security approval. Подписанный release пока отсутствует.

## Что означает «без исходников»

Собственные runtime-модули Uter скомпилированы Nuitka в ELF .so. Проверены все слои
на .py/.pyc/.pyo, .git и .env под /app; imports выполняются как extension modules.
С 26.10.2026 сканер проверяет пути во всех слоях, вложенные ZIP/TAR-архивы с лимитами,
image config и точные SHA-256 исходных Python-файлов при передаче --source-root.
Python-файлы в явно разрешённых каталогах сторонних библиотек допустимы; хеши
собственных исходников проверяются и там. Это не семантическая аттестация каждого
стороннего пакета или модели: изменённые исходники и произвольные форматы кодирования
требуют отдельного анализа, secrets-аудит Trivy остаётся отдельной проверкой.
Python-код сторонних библиотек и контроллера установки может оставаться открытым.
Политики, профили, веса моделей и строки в бинарниках не считаются зашифрованными.

[Nuitka documentation](https://nuitka.net/user-documentation/user-manual.html)
описывает компиляцию модулей; компиляция не является криптографической защитой.

При доступе администратора к локальному серверу практическая оценка такая:

| Цель | Оценка |
|---|---|
| Скопировать образ и .so | Технически доступно администратору |
| Прочитать поставленные конфиги, политики и модели | Доступно; не защищено компиляцией |
| Извлечь часть строк, имён, промптов, наблюдать API | Реалистично; подтверждено статическим анализом; см. image-protection.md |
| Восстановить часть алгоритмов и сделать функциональный аналог | Возможно; нужны опыт, время и тестирование |
| Получить точные первоначальные Python-файлы с комментариями | Не равнозначно декомпиляции; исходный текст не сохраняется как такой артефакт |

Численную вероятность реверса нельзя обоснованно назвать без модели атакующего,
сроков, бюджета и практического исследования. Выполнены ограниченные статические проверки строк/ELF и добавлена runtime-попытка
inspect.getsource; это не полноценная red-team оценка стойкости к реверсу.
Контейнеризация, offline-режим и файловые права не скрывают реализацию от root хоста.
Если требование — чтобы организация вообще не могла исследовать чувствительную
логику, локальное развёртывание не обеспечивает его; нужен отдельный доверенный сервис
для этой логики. Это иной вариант архитектуры и он сейчас не реализуется.
